# 新手人物卡说明与装备设计

状态：已确认并实施。2026 年 10 月 4 日，用户先确认 Q1–Q7，再确认 Q8–Q10，设计访谈收敛。

## 已确认

1. 属性与体格的分段文字仅辅助理解和扮演，不增加能力限制或修改机械规则。各属性按自己的含义解释，不将 SIZ 固定换算为公斤，也不将 EDU 固定对应学历。
2. 财富信息服务建卡参考，并允许玩家独立记录实际现金。生活水平、起始可用现金与资产参考跟随适用规则；玩家通过明确操作填入金额，信用变化不自动覆盖实际记录。
3. 武器与其他物品分区，同一件东西只录一次。徒手作为每位人物的固有攻击方式始终显示，不作为可携带物品添加。
4. 技能简介提供悬停、键盘聚焦和点击入口；属性与体格的短描述直接放在数值旁。技能说明与场景示例维护在 JSON 中。
5. 护甲先提供手动填写的护甲值、防护来源及适用说明。不预设多件护甲的叠加，不根据穿戴装备自动计算。
6. 规则按核心共享内容与扩展差异拆为不同 JSON；保留现有 ID，避免重复维护通用技能说明。
7. 新建与编辑人物通过职业卡片弹窗选择职业。卡片展示简介、信用范围与技能标签，展开查看完整要求；选中后确认应用。更换职业保留已分配点数，提示不符合新职业的加点，职业专属可选槽位重新选择。

## 第二轮确认

8. 属性按 1–24、25–44、45–64、65–84、85–99 五段写原创扮演提示。体格分别解释 −2、−1、0、1、2，强调力量与体型的综合表现；不扩大现有属性输入范围。
9. 财富先展示已核实的生活水平与财产概念，金额由玩家填写；未核实对应时代金额表前不自动生成起始现金。黑暗时代解释社会地位，不套用现代生活水平或金额公式。
10. 已有未修改的标准徒手只显示一次；修改过的徒手保留为手动攻击记录，同时提供标准徒手。

## 实施边界

- 核心与五个时代 profile JSON 通过统一加载入口组合；维多利亚继承煤气灯的共享差异。保留原目录 ID、机械数值、顺序、备注与来源。
- 69 项预置技能均有原创中文简介和场景；时代含义变化通过 profile 覆盖说明。原创技能简介、场景和武器的类型、技能关联可以保存与导入。
- 武器与物品使用同一份持有记录，按明确分类分区；旧记录通过目录定义或伤害字段判断，玩家可以修改分类。标准徒手是显示时提供的固有攻击，不反复写入库存。
- 护甲由人物手动记录；旧人物缺少护甲时默认 0。信用与时代变化不会改写实际财产。
- 保持 schemaVersion 1 与既有本地存储键。导入继续检查字段和引用，HTML 输出继续转义文字；缺少新增说明字段的旧标准重复定义仍可识别。
- HTML/PDF 同步呈现属性、体格、护甲、武器与物品分区及生活说明。

## 验证

Node.js 22 下 `npm run check` 通过：57 项测试（含 14 项 Chromium 实际 PDF 回归）与生产构建全部通过。

覆盖说明区间、时代语义、规则分包引用与冲突、徒手去重、库存未知定义、旧存档、新字段校验及导出转义。手动检查桌面和手机的职业确认/取消、新建流程、技能说明悬停/聚焦/点击、护甲与财产持久化、换职业及时代保留技能数据。

合入 master 的 PDF 分页门禁；六种时代、四份样例、手机打印及已填写护甲说明均保持两页，长技能与背景内容可自然增页。打印通过收紧空白容纳新增说明，保留技能数字字号与全部内容，并目检实际 PDF。

## 已核对的现状

目录已有徒手条目，但新人物不默认呈现；护甲没有人物字段；财产已有独立自由文本；技能缺少说明；职业已有简介但选择入口为下拉框。技能与物品的现有 ID、旧存档、自定义导入及时代切换中已分配的技能数据需要保留。
